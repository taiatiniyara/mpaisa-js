Built for the M-PAiSA IPG API v1.3

Accept M-PAiSA payments in TypeScript.

The official-community SDK for Vodafone Fiji's M-PAiSA Payments Gateway. Handshake, tamper-proof redirect verification, and transaction status — in one zero-dependency package.

Get started See the flow

import { Mpaisa } from "mpaisa-js";

const mpaisa = new Mpaisa({
  clientId: process.env.MPAISA_CLIENT_ID!,
  clientSecret: process.env.MPAISA_CLIENT_SECRET!,
  environment: "staging",
});

// 1. Open a session
const session = await mpaisa.handshake({
  merchantTid: "123456543VF",
  amount: "10.50",
  itemDetail: "iPhone 17",
  returnUrl: "https://example.com/callback",
});
session.verifyDigest();

// 2. Redirect the customer
redirect(session.checkoutUrl);

// 3. On return — verify, then confirm
const txn = await mpaisa.confirmRedirect(params);
if (txn.status === "SUCCESS") fulfilOrder();

Built safe by default

Payments code fails quietly unless the SDK makes the safe path the easy path.

🔐

Tamper-proof redirects

tokenv2 digests are recomputed locally with timing-safe comparison. Verification failures are impossible to ignore — the type system forces you to handle them.

🧾

Ground-truth confirmation

confirmRedirect() verifies the hash and re-checks authoritative status via the gateway before you fulfil an order. Never trust the redirect alone.

🪶

Zero dependencies

Pure fetch + WebCrypto. Runs on Node 18+, Bun, Deno, and Cloudflare Workers without polyfills or audit surface.

🔄

Token lifecycle handled

Bearer tokens are fetched lazily, cached, and refreshed ahead of expiry. Plug in an external cache for serverless cold starts.

💸

Exact money strings

Amounts are decimal strings reused byte-for-byte across URLs and digests — no float formatting drift breaking hash verification.

🧭

Typed end to end

Every response code (100–155) mapped to typed errors. Dual ESM/CJS output with strict TypeScript declarations.

The payment flow

Four calls between your server, the customer's browser, and the gateway.

Handshake

Your server exchanges credentials for a bearer token, Request ID, and auth digest — verified locally before anything moves.

Redirect

The customer is sent to the gateway-hosted Payments Page and pays with their M-PAiSA wallet via SMS/OTP two-factor auth.

Redirect back

The gateway returns the customer with rCode, transaction details, and a tokenv2 hash. mpaisa-js recomputes and compares it before you act.

Confirm & fulfil

confirmRedirect() pulls authoritative status from the requeststatus API. Only then do you fulfil the order.

Integration note: always verify tokenv2 and confirm status server-side before fulfilling orders. Unverified redirects are vulnerable to tampering — Vodafone accepts no liability for unverified transactions. mpaisa-js makes skipping these checks hard on purpose.
